# Как помочь проекту

Спасибо за интерес к Self-Hosted Browser VPN. Это MVP: расширение направляет обычные веб-запросы Chrome через HTTPS-прокси на собственном сервере. Оно не создаёт системный VPN. Перед предложением изменений прочитайте [границы работы](docs/architecture.md) и [модель безопасности](docs/security.md). Сообщения и pull request можно писать по-русски или по-английски.

## Ошибки и предложения

- Для ошибки используйте [шаблон issue](https://github.com/coffegorio/self-hosted-browser-vpn/issues/new/choose). Укажите шаги воспроизведения, ожидаемое и фактическое поведение, версии Chrome, ОС хоста и Docker Compose либо Ubuntu, способ установки и компонент проекта.
- Для новой функции опишите задачу пользователя и желаемое поведение. Особенно важно указать, как предложение влияет на маршрутизацию, безопасность и простоту установки.
- Уязвимости сообщайте по [правилам безопасности](SECURITY.md). Не публикуйте детали эксплуатации в открытом issue.
- Никогда не прикладывайте ключ `shbvpn1:…`, пароль VPS или прокси, приватные TLS-ключи, полные конфигурации с учётными данными и журналы без удаления секретов. При утечке ключа смените пароль: `sudo shbvpn --rotate` для Ubuntu или `rotate` и перезапуск прокси по [руководству Compose](deploy/README.md).

## Pull request

1. Создайте ветку от актуальной `main` и внесите одно логическое изменение.
2. Добавьте или обновите проверки, если меняется поведение прокси, установщика, контейнеров либо расширения. Для изменения интерфейса приложите снимок экрана без секретов.
3. Обновите документацию, если меняются установка, разрешения Chrome, формат ключа, маршрутизация или ограничения.
4. В описании PR объясните проблему, новое поведение, выполненные проверки и возможное влияние на существующие установки.

Локальные команды проверки приведены в [руководстве разработчика](docs/development.md). Основные проверки:

```bash
(cd server && go test -race ./... && go vet ./...)
(cd extension && npm test)
node --test tests/extension_routing.mjs
for script in installer/*.sh; do
  bash -n "$script" || exit
done
python3 -m py_compile installer/*.py deploy/*.py tests/*.py
python3 -m unittest discover -s tests -p 'test_*.py'
```

Для проверки сетевого пути отдельно запустите `python3 tests/smoke_proxy.py`; ему нужен доступ к публичному HTTPS-сайту. Изменения установщика дополнительно проверяйте на тестовом VPS, прежде чем применять на рабочем сервере. Не добавляйте в репозиторий локальные ключи, сертификаты, артефакты сборки и зависимости.

При изменениях в `deploy/` проверьте Compose-конфигурацию и сборку образов по [руководству разработчика](docs/development.md). CI также собирает образы и проверяет их точки входа. Выпуск и продление сертификата требуют отдельной проверки на доступном извне тестовом хосте.
