# Безопасность и модель доверия

Сервер и расширение рассчитаны на личный VPS. Это не сервис анонимности и не замена системному VPN. Перед использованием для чувствительных задач оцените [границы маршрутизации](architecture.md) и проверьте свою сеть.

## Кому вы доверяете

Браузер устанавливает TLS-соединение с HTTPS-прокси на вашем VPS и проверяет его обычным хранилищем доверенных сертификатов. Прокси требует HTTP Basic-авторизацию внутри этого TLS-соединения. VPS знает адреса назначения; для обычного HTTP он также видит содержимое запроса и ответа. При HTTPS через `CONNECT` содержимое сайта остаётся защищено отдельным TLS между браузером и сайтом, но адрес назначения виден прокси. Хостинг-провайдер и внешние сайты могут видеть сетевые соединения и исходящий адрес VPS.

Расширение запрашивает разрешения Chrome `proxy`, `privacy`, `storage`, `webRequest`, `webRequestAuthProvider` и доступ к URL для авторизации на собственном прокси и проверки IP. Исходный код расширения находится в [`extension/`](../extension). Встроенная кнопка проверки отправляет запрос стороннему сервису `api.ipify.org`; без её нажатия этот тест не запускается.

## Ключ подключения

Ключ `shbvpn1:…` содержит адрес, порт, имя пользователя и **пароль** в JSON, закодированном base64url. Кодирование **не шифрует** данные. Любой получивший ключ может использовать ваш прокси до смены пароля.

- Не добавляйте ключ и файл `/etc/shbvpn/credentials` в Git, issue, логи CI, снимки экрана и чаты.
- Храните ключ как пароль. На сервере получайте его командой `sudo shbvpn --show-key` только тогда, когда он нужен.
- Расширение хранит разобранный ключ в `chrome.storage.local` и ограничивает доступ доверенными контекстами расширения. Оно не шифрует файлы профиля Chrome. Защитите локальную учётную запись и диск компьютера.
- Если ключ раскрыт, выполните `sudo shbvpn --rotate`, затем замените ключ в расширении. Старые учётные данные немедленно перестанут работать.

Сервер принимает подключения со всех сетевых интерфейсов на выбранном порту; сильный случайный пароль генерируется установщиком. Дополнительного ограничения по IP клиента, двухфакторной авторизации и ограничения частоты попыток в MVP нет. Защитите доступ к VPS и при необходимости ограничьте входящий порт своим файрволом, учитывая сети, из которых будете подключаться.

## Защита сервера

Сервер разрешает соединения только с публичными IP-адресами на портах `80`, `443`, `8080`, `8443` и `9443`. Он отклоняет локальные, частные, link-local, документированные тестовые и некоторые служебные диапазоны. Это снижает риск использования прокси для доступа к внутренним службам VPS, но не заменяет изоляцию хоста и регулярные обновления системы.

Службы прокси и ACME работают от отдельного пользователя `shbvpn` с ограничениями systemd. Установщик запускается с правами root, потому что устанавливает пакеты и службы и получает сертификат. Проверяйте код и изменения перед повторной установкой из обновлённого репозитория.

Сертификат Let's Encrypt автоматически проверяется на продление таймером `shbvpn-renew.timer`. Для IP-сертификатов срок действия короткий; оставьте **80/TCP** открытым для HTTP-01 и контролируйте таймер. Не отключайте проверку TLS-сертификата в браузере и не используйте самоподписанный сертификат как постоянную замену.

## Что расширение не гарантирует

PAC-правило содержит только прокси для обычных сайтов и `DIRECT` для ваших исключений; запасного прямого маршрута для проксируемых сайтов в нём нет. При этом Chrome может обходить прокси для локальных адресов и собственных операций. DNS, IPv6, WebRTC, инкогнито и конфликты настроек требуют проверки на конкретной системе. Ограничение прямого UDP для WebRTC может нарушить работу видеозвонков. UDP/QUIC сервер не проксирует.

Статус **ON** подтверждает настройки Chrome, а не полную приватность и не доступность сервера. Проверяйте внешний IP и поведение нужных сайтов. Если Chrome сообщает о возможном прямом соединении или конфликте, расширение показывает ошибку; считайте такую ситуацию требующей диагностики.

## Сообщить об уязвимости

Не публикуйте рабочие ключи и приватные данные в открытом issue. Если в репозитории включена функция GitHub **Private vulnerability reporting**, используйте её для непубличного сообщения; иначе создайте issue без эксплуатационных подробностей и попросите владельца проекта указать приватный канал связи.
