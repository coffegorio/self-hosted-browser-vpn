# Установка на VPS

Эта инструкция устанавливает HTTPS-прокси на вашем сервере и получает сертификат Let's Encrypt. Расширение Chrome устанавливается отдельно на компьютере: [подключение браузера](usage.md).

## 1. Подготовьте сервер

Поддерживаются **Ubuntu 24.04 и 26.04** на VPS с публичным IPv4-адресом, доступом `sudo` и установленным `git` для копирования проекта. Для установки требуются подключение к репозиториям Ubuntu и к Let's Encrypt; для варианта с Python venv также нужен доступ к PyPI. Установщик запускается с правами root: перед запуском вы можете прочитать [его исходный код](../installer/install.sh).

| Порт на VPS | Для чего | Когда нужен |
| --- | --- | --- |
| `80/TCP` | Проверка владения адресом через ACME HTTP-01 | Всегда, при выпуске и продлении сертификата |
| `443/TCP` | HTTPS-прокси | По умолчанию |
| `8443/TCP` или другой свободный | HTTPS-прокси вместо 443 | Если выбрано через `--port` |

Откройте **80/TCP и выбранный порт прокси** во внешнем файрволе или панели провайдера. Если UFW уже активен, установщик добавит нужные правила сам. Если UFW выключен, он его не включает. Для продления сертификата 80/TCP должен оставаться доступным извне.

Если используете домен, заранее направьте его A-запись на публичный IPv4 VPS. Для варианта без домена укажите сам публичный IPv4 через `--ip`. Сейчас установщик не принимает IPv6 как идентификатор сертификата.

Проверьте, что порты свободны:

```bash
sudo ss -ltnp '( sport = :80 or sport = :443 or sport = :8443 )'
```

Если другой сервис занимает 443/TCP, установите прокси на 8443/TCP. Например, так можно разместить его рядом с уже работающим VPN-сервисом. **80/TCP тоже должен быть свободен**: установщик запускает на нём отдельный сервер для ACME-проверки. Если порт 80 занят, сначала решите вопрос с существующим сервисом; установщик не встраивается в его веб-сервер.

## 2. Скопируйте проект и запустите установку

Подключитесь к VPS по SSH. Команды ниже выполняются **на VPS**, не в терминале Chrome-компьютера:

```bash
git clone https://github.com/coffegorio/self-hosted-browser-vpn.git
cd self-hosted-browser-vpn
sudo bash installer/install.sh --ip ВАШ_ПУБЛИЧНЫЙ_IPV4
```

Для занятого 443/TCP:

```bash
sudo bash installer/install.sh --ip ВАШ_ПУБЛИЧНЫЙ_IPV4 --port 8443
```

Для собственного домена:

```bash
sudo bash installer/install.sh --domain proxy.example.com --email you@example.com
```

Параметры `--ip` и `--domain` взаимоисключающие. `--port` необязателен и по умолчанию равен 443. `--email` необязателен. Замените значения примера на свои.

Установщик добавляет системного пользователя `shbvpn`, собирает Go-сервер, создаёт службы `shbvpn-proxy.service` и `shbvpn-acme.service`, получает сертификат и запускает таймер `shbvpn-renew.timer`. Он проверяет локально TLS, отказ без авторизации и блокировку локального адреса; затем выполняет пробное продление и проверяет перезапуск прокси после него. Успешное завершение печатает ключ `shbvpn1:…`. Сохраните его как пароль и [импортируйте в Chrome](usage.md).

Если Certbot для IP-сертификата старее 5.4, установщик остановится с ошибкой. На обычной установке используется Certbot из snap. На Ubuntu 26.04, когда `snapd.service` или `snapd.socket` замаскирован, установщик использует изолированный Certbot 5.8.0 в Python venv. В этом случае системный Certbot и блокировка snapd не меняются. При уже установленном старом Certbot snap потребуется обновить его отдельно и повторить команду установки.

## 3. Проверьте службу и продление

На VPS:

```bash
sudo systemctl is-active shbvpn-proxy.service shbvpn-acme.service shbvpn-renew.timer
sudo systemctl is-enabled shbvpn-renew.timer
sudo systemctl list-timers shbvpn-renew.timer
sudo python3 /usr/local/share/shbvpn/installer/healthcheck.py
```

Первые три службы должны быть активны, таймер — включён. Локальная проверка должна закончиться строкой `TLS, authentication and destination guard: OK`. Она не проверяет доступность VPS с вашего компьютера: после установки [подключите расширение и проверьте IP из Chrome](usage.md).

Таймер дважды в день проверяет необходимость продления сертификата. При успешном продлении deploy hook копирует сертификат в каталог прокси и перезапускает его. Следите за состоянием таймера: сертификаты для IP имеют короткий срок действия. При проблемах смотрите [диагностику](troubleshooting.md).

## Обновление и удаление

Для обновления кода получите изменения в той же копии проекта и **повторите прежнюю команду установки с тем же адресом и портом**:

```bash
cd self-hosted-browser-vpn
git pull --ff-only
sudo bash installer/install.sh --ip ВАШ_ПУБЛИЧНЫЙ_IPV4 --port 8443
```

Последняя строка — пример для установки на 8443. Используйте `--domain`, если изначально указывали домен. Повторная установка с другим адресом или портом не поддерживается: для изменения этих параметров удалите прежнюю установку и установите заново. При обновлении запланируйте короткий перезапуск прокси.

После установки доступна команда управления, даже если исходную копию проекта удалили:

```bash
sudo shbvpn --show-key
sudo shbvpn --rotate
sudo shbvpn --uninstall
```

`--rotate` выдаёт новый ключ и немедленно делает старый недействительным. `--uninstall` останавливает и удаляет службы, конфигурацию и ключ проекта; также пытается удалить его сертификат и правила UFW, добавленные установщиком. Общие пакеты Go/Certbot остаются установленными. Подробнее о ключе: [использование](usage.md) и [безопасность](security.md).
