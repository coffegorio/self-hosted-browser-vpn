# Подключение Chrome и повседневное использование

Сначала установите серверную часть [через Docker Compose](../deploy/README.md) либо [на Ubuntu без Docker](installation.md). Нужен Chrome версии **108 или новее**. На компьютере, где вы используете Chrome, откройте [страницу проекта](https://github.com/coffegorio/self-hosted-browser-vpn), нажмите **Code → Download ZIP** и распакуйте архив. Папка `extension` нужна локально для загрузки расширения. Сборка, npm и установка зависимостей для работы расширения не требуются.

## Добавить сервер

1. В Chrome откройте `chrome://extensions`.
2. Включите **Режим разработчика** и нажмите **Загрузить распакованное расширение**.
3. Выберите папку `extension` проекта на своём компьютере.
4. Закрепите значок **Self-Hosted Browser VPN** на панели Chrome и откройте его.
5. Вставьте ключ, полученный при установке, и нажмите **Добавить сервер**. Для повторного получения на Ubuntu без Docker выполните `sudo shbvpn --show-key`; в Docker используйте [команду `show-key`](../deploy/README.md#управление).
6. Нажмите **Подключить**, затем **Проверить внешний IP**. Адрес должен соответствовать исходящему адресу хоста прокси. Если хост выходит в интернет через NAT или IPv6, адрес может отличаться от того, который вы указали в ключе.

Значок **ON** показывает, что Chrome принял настройки прокси и ограничения WebRTC. Это не проверка сетевой доступности сервера. Кнопка **Проверить внешний IP** отправляет запрос к `https://api.ipify.org` через текущие настройки Chrome и показывает увиденный сервисом адрес. Если сервис недоступен, проверка выдаст ошибку; отдельно откройте нужный сайт и проверьте его работу.

Настройка действует в обычном профиле Chrome, в котором загружено расширение. Системные приложения и другие профили Chrome используют свои настройки подключения. Для режима инкогнито нужно явно разрешить расширение в настройках Chrome и отдельно проверить работу соединения и авторизации; автоматического обещания защиты инкогнито нет.

## Подключить, отключить и удалить ключ

- **Подключить** включает настройки прокси и ограничение прямого UDP для WebRTC в текущем профиле.
- **Отключить** снимает настройки расширения. Chrome возвращается к остальным применимым настройкам подключения; ключ и исключения остаются сохранёнными.
- **Заменить сервер** импортирует новый ключ, отключает текущее подключение и очищает список исключений. После замены нажмите **Подключить**.
- **Удалить сохранённый ключ** отключает расширение, удаляет ключ и исключения из его локального хранилища.

Если пароль был сменён, старый ключ перестаёт подходить. На Ubuntu без Docker используйте `sudo shbvpn --rotate`; в Docker выполните [команду `rotate` и перезапустите прокси](../deploy/README.md#управление). Получите новый ключ из вывода команды, выберите **Заменить сервер** в расширении и подключитесь снова.

## Исключения для сайтов

Откройте **Исключения для сайтов**, введите по одному домену в строке и нажмите **Сохранить исключения**:

```text
example.com
intranet.example.org
```

`example.com` означает сам домен **и все его поддомены**. Запись `*.example.com` приводит к тому же результату. Схемы (`https://`), пути и маски других форм не принимаются. Допускается до 100 исключений. Исключённые сайты открываются **напрямую с вашего обычного подключения**; их внешний IP может быть не IP хоста прокси. Не добавляйте `api.ipify.org`, если хотите использовать встроенную проверку IP: расширение сообщит, что сервис проверки находится в исключениях.

Исключения применяются по имени хоста в PAC-правиле. Это не фильтр доступа и не список IP-подсетей. После сохранения проверьте поведение нужных сайтов, особенно если Chrome или другое расширение управляет своими правилами маршрутизации.

## Как понять статус

| В интерфейсе | Значение | Действие |
| --- | --- | --- |
| **Сервер не добавлен** | Нет сохранённого ключа | Импортируйте ключ |
| **Отключено** | Прокси расширения снят | Нажмите **Подключить** |
| **Маршрутизация включена**, **ON** | Chrome принял настройки | Проверьте внешний IP и нужный сайт |
| **Конфликт настроек**, **!** | Расширение не управляет прокси | Проверьте другие расширения и политики Chrome |
| **Нужна проверка**, **!** | Chrome сообщил об ошибке прокси либо настройка отличается | Откройте [диагностику](troubleshooting.md); после временной ошибки нажмите **Повторить проверку IP** |

Если веб-страница перестала открываться, сначала проверьте статус расширения и доступность хоста прокси. У проксируемых сайтов PAC-правило не содержит запасного прямого маршрута, но внутренние механизмы Chrome и явные исключения могут работать иначе. Точные границы описаны в [архитектуре](architecture.md).
