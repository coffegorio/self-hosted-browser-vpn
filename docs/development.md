# Разработка и проверка

Проект — небольшой MVP без внешних JavaScript-зависимостей в расширении и без сторонних Go-библиотек на сервере. Для локальной проверки нужны Go 1.22+, Node.js, Python 3.9+, OpenSSL, curl и доступ к публичному HTTPS-сайту для smoke-теста. Установщик Ubuntu использует пакет Go из Ubuntu; контейнерный вариант собирает сервер внутри Docker-образа.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| [`server/`](../server) | HTTPS-прокси, авторизация, HTTP/CONNECT, защита адресов, ACME HTTP-01 |
| [`installer/`](../installer) | Установка Ubuntu, systemd, Certbot, ключ, проверка, смена пароля и удаление |
| [`deploy/`](../deploy) | Docker Compose, сборка образов и управление сертификатом для Linux, macOS и Windows с Linux-контейнерами |
| [`extension/`](../extension) | Расширение Chrome Manifest V3 и его локальные тесты |
| [`tests/`](../tests) | Интеграционный smoke-тест прокси и проверка PAC-маршрутизации |

## Локальные проверки

Из корня репозитория:

```bash
(cd server && go test -race ./... && go vet ./...)
node --test tests/extension_routing.mjs
(cd extension && npm test)
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tests/smoke_proxy.py
```

Smoke-тест временно собирает Go-сервер, создаёт тестовый TLS-сертификат и случайные учётные данные во временном каталоге, запускает прокси на локальном свободном порту и удаляет всё после завершения. Он проверяет TLS, отказ без авторизации, `CONNECT` к публичному HTTPS-сайту, блокировку внутренних, служебных и собственного адреса и закрытие соединения после остановки. Тесты Go также проверяют потоковые HTTP-ответы, Upgrade, DNS-псевдонимы собственного адреса и временную ошибку DNS. Для другого публичного назначения используйте `--public-target example.org:443`; подробности в [`tests/README.md`](../tests/README.md).

Для расширения можно открыть `chrome://extensions`, загрузить папку `extension` как распакованное расширение и нажать **Обновить** после изменения файлов. Сам `npm test` не загружает браузер и не проверяет реальную прокси-маршрутизацию Chrome.

При наличии Docker проверяйте описание Compose и сборку образов:

```bash
docker compose --env-file deploy/settings.env.example -f deploy/compose.yaml config --quiet
docker compose --env-file deploy/settings.env.example -f deploy/compose.yaml build
```

Эти команды не подтверждают выпуск сертификата или работу опубликованных портов: для этого нужны доступный извне тестовый хост, реальные адрес/домен и проверка из Chrome.

## Проверка на хосте

После установки проверьте активность служб, сертификат, продление и внешний IP из Chrome по [инструкции Ubuntu](installation.md), [инструкции Compose](../deploy/README.md) и [инструкции использования](usage.md). Локальные тесты и зелёный значок **ON** по отдельности не доказывают, что сервер доступен из сети пользователя. Если изменили серверный код, повторите smoke-тест и проверьте работу на тестовом хосте, прежде чем обновлять рабочую установку.

При отчёте об ошибке приложите шаги воспроизведения, версии ОС, Docker либо Ubuntu, Chrome и Go при локальной сборке, команду установки без секретов и относящиеся к проблеме строки журналов. Ключ `shbvpn1:…`, учётные данные и приватные TLS-ключи не прикладывайте. [Создать issue](https://github.com/coffegorio/self-hosted-browser-vpn/issues).
